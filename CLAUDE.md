# askeza

Приложение для отказа от вредных привычек. Помогает отслеживать время без привычки,
видеть, как слабеет тяга, проходить фазы восстановления и держать аскезы — обеты
воздержания на конкретный срок.

## Структура репозитория

```
index.html            — askeza 2. Весь код приложения (HTML + CSS + JS)
sw.js                 — service worker: офлайн
manifest.webmanifest  — PWA-манифест
icon-180.png          — иконка для iOS (37 КБ)
icon-512.png          — иконка для манифеста
tests/run.mjs         — 279 автотестов (Playwright)
v1/                   — askeza 1 (v1.4.0). ЗАМОРОЖЕНА. Не трогать
askeza2/index.html    — заглушка со старого адреса: снимает старый service
                        worker и уводит в корень. Не удалять
V2.md                 — ревью v1 и план v2
CLAUDE.md             — этот файл
```

# askeza 2 — активная версия

**Текущая версия: `v2.6`**

## Стек

- Single-file PWA (HTML + CSS + JS в одном `index.html`), ноль зависимостей
- Системный шрифт (`-apple-system` / SF Pro) — никаких внешних запросов
- Данные: `localStorage`, полностью на устройстве
- Целевая платформа: нативное iOS-приложение (App Store)

## Два архетипа привычки

Привычки разного формата не помещаются в одну механику, поэтому их две.
Архетип задаётся типом привычки (`KINDS[kind].mode`), а не отдельным полем.

| | **Отказ** (`abstain`) | **Режим** (`daily`) |
|---|---|---|
| Типы | курение, алкоголь, марихуана, скроллинг, порно, своя | режим сна |
| Серия | непрерывный таймер с даты отказа | дни подряд с отметкой |
| Обрывается | срывом | проспанным или пропущенным днём |
| Экран привычки | число дней, тяга, одометр | отметка дня, календарь, статистика |

Общее для обоих: карточка в списке с полосой ступеней, крупное число дней, цитата.

## Модель данных

```js
habit = {
  id, name,
  kind: 'smoking'|'alcohol'|'weed'|'scroll'|'porn'|'sleep'|'custom',  // тип, а НЕ регулярка
  color, emoji,
  startedAt,                                          // начало серии / старт режима
  sid,                                                // номер серии: растёт при срыве
  daily: { wakeBy:'07:00', checks:{ 'YYYY-MM-DD':{ok,at} } },   // только у режима
  history: [                                          // всё, что было
    { t:'start',     at },
    { t:'relapse',   at, streakDays, note? },
    { t:'wake',      at, day, time },                 // встал вовремя
    { t:'oversleep', at, day, time },                 // проспал
    { t:'legacy',    at, label, note },               // перенос из askeza 1
  ],
}
```

Журнал `history` **никто не читает**: экрана истории нет, вех нет. Он остаётся
как единственная запись о том, что срыв был, и как место для меток `legacy`
при переносе из v1. Если решим, что и это не нужно, его можно убрать целиком —
но тогда данные о прошлых сериях исчезнут безвозвратно.

Ключи хранилища: `askeza2_data` (основной), `askeza2_backup` (автокопия).
`askeza_data` — данные старого приложения, **только чтение**, никогда не пишем.

## Один принцип прогресса

**Полоса в списке — единственная мера прогресса.**

Одна сущность, один вопрос: сколько пройдено. Ни рангов, ни тиров, ни уровней,
ни празднований. В v2.4 удалены фазы, аскезы, история и «Тянет», в v2.6 — вехи
вместе с экраном празднования. Приложение ничего не празднует и никуда не зовёт:
зашёл, увидел числа, вышел.

## Что реализовано

### Ядро
- Несколько привычек, переключение через список, редактирование, удаление
- Тип привычки задаётся при создании и переживает переименование
- Календарно корректный отсчёт (настоящие месяцы, не «30 дней»)
- Русская плюрализация везде (`1 день`, `21 день`, `22 дня`, `25 дней`)
- Экранирование пользовательского ввода, обработчики через делегирование
- Автоматическая резервная копия в `askeza2_backup`, восстановление из битого хранилища
- Автоперенос из askeza 1 при первом запуске (старые данные не меняются)

**Экрана экспорта и импорта нет.** Данные живут только в `localStorage` этого
браузера: очистка данных сайта стирает их безвозвратно. Это осознанный выбор в
пользу чистого экрана.

### Загрузка по ссылке
Единственный способ положить в приложение готовые данные — адрес вида
`/askeza/#seed=<base64url JSON>`:

```json
{ "habits": [ { "name": "Курение", "kind": "smoking", "startedAt": "2025-12-25T06:00:00" } ] }
```

Дата **без часового пояса** читается как местное время: «06:00» останется шестью
утра на том телефоне, где ссылку открыли. `kind` берётся из `KINDS`, цвет
подставляется по типу, если не задан явно.

Ссылка **полностью заменяет** содержимое хранилища, поэтому приложение сначала
спрашивает подтверждение — иначе старая ссылка, открытая через полгода, молча
стёрла бы весь прогресс. Хеш убирается из адреса сразу, так что перезагрузка
не спрашивает второй раз.

Данные едут в самой ссылке, а не в коде: репозиторий публичный, и список
привычек с датами не должен в нём лежать.

### Список привычек — корневой экран
Главная функция приложения: зашёл, увидел прогресс всех привычек разом, вышел.

- Карточка: цветная метка, название, серия в днях, полоса прогресса
- **Полоса** — восемь ступеней до года: `1 день · 3 дня · неделя · 2 недели ·
  месяц · 3 месяца · полгода · год`. Деления одинаковой ширины, хотя стоят за
  разный срок: первые дни самые трудные и должны давать самое заметное движение.
  Пройденное деление горит цветом привычки, текущее подливается плавно и
  вполовину бледнее. Год = победа: дальше полоса полная, растёт только число
- До года крупное число — дни (`242 дня`), после — `1 год 40 дней`
- Свайп влево — «Изменить» и «Удалить»; карточка уезжает под кнопки и гасит
  содержимое, цветная метка остаётся на месте. Открыта всегда одна карточка
- Долгий тап — перетаскивание, порядок сохраняется
- Тап по карточке открывает экран привычки, стрелка возвращает назад

### Экран привычки
- Крупное число дней — герой экрана, без кольца вокруг
- Карточка тяги с живым числом (10 Гц, динамическая точность) и зоной
- Одометр: 6 полос с непрерывно текущей секундной
- Цитата, меню «…»: изменить, записать срыв, удалить
- Фон подкрашивается цветом привычки

### Режим сна
- Цель: встать до заданного времени. Одна кнопка «Я проснулся» фиксирует время сама
- Серия = дни подряд; незакрытый сегодняшний день серию не обрывает — он ещё идёт
- Пропущенные дни можно закрыть задним числом за последние трое суток
- Календарь на пять недель, статистика: вовремя / проспал / средний подъём
- Точное время подъёма правится на отдельном экране дня

### Тяга (курение / алкоголь / марихуана)
- Кривые построены на опорных точках из исследований, интерполяция PCHIP
  в лог-пространстве дней: монотонная, проходит точно через данные
- Курение переведено с формулы `99/√(1+дни)+1` на опорные точки: пик держится
  первые 1–3 дня, как в реальных данных
- График: два слоя канваса (статический + живая точка), реальный DPR

У скроллинга и порно графика тяги нет: данных уровня никотиновых там не существует,
а рисовать кривую без данных значило бы обесценить те, что построены на исследованиях.

### Навигация «назад»
Приложение **не создаёт записей в истории браузера** — намеренно. Раньше оно
клало пустышку через `pushState`, чтобы жест «назад» закрывал открытый экран, а
не выбрасывал из приложения. Но Safari не делает снимок для записи, добавленной
`pushState` в том же документе, и при свайпе от левого края показывал вместо неё
белый прямоугольник на несколько секунд. Снимка нет и не будет, поэтому лечится
это только отказом от лишних записей: без них свайпу некуда возвращаться и он
ничего не делает. Экраны закрываются стрелкой, шит — кнопкой.

**Не возвращать `pushState`, не разобравшись с белым экраном.**

### Производительность и доступность
- Один rAF-цикл: секунда — полное обновление, 10 Гц — тяга, кадр — только секундная полоса
- Запись в DOM только при изменении значения
- Пауза в фоне (`visibilitychange`)
- `prefers-reduced-motion`, `aria-label`, зум не заблокирован
- Service worker: network-first для HTML, stale-while-revalidate для остального

## Тесты

```bash
node tests/run.mjs
```

279 проверок: чистые функции, все экраны, оба архетипа, срывы,
список привычек (полоса делений, свайп, перетаскивание, навигация),
режим сна (отметки, серия, пропуски, календарь, статистика), перенос из v1,
XSS, устойчивость к битым данным, доступность. Отдельная группа следит за тем,
что удалённое в v2.4–v2.6 не вернулось.
Скриншоты кладутся в `tests/shots/` (не коммитятся).

**Перед каждым коммитом прогонять тесты.**

## Версионирование

При **каждом** изменении:

1. Поменять версию в `index.html` — константа `VERSION`
2. Поменять версию в `CLAUDE.md` — строка `**Текущая версия**` выше
3. Прогнать тесты
4. Запушить (`git add -A && git commit -m "vX.Y ..." && git push`)

Схема: `v[major].[minor]`.
